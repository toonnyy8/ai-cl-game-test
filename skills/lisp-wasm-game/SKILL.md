# Lisp → wasm games on the RAVEN EDGE engine

## Overview
The exemplar is `toonnyy8/ai-cl-game-test` (local copy: `/media/8tsp/projects/ai-cl-game-test`): `engine/` (package
ENGINE) plus one directory per game (`game/` RAVEN EDGE, `duel/` SOUL DUEL), `examples/hello` as the template. Core
principle: **the engine knows no game; a game is a MANIFEST of Lisp files that calls `run-game`, and everything the
player sees or hears is built by code at startup.** The full lesson list with evidence is in `reference.md` (read the
section you need, not the whole file).

## Day one for a new game (in this order, all green before gameplay)
1. Copy `examples/hello` → `<game>/`; `MANIFEST` first line `# title: NAME`, then sources in dependency order.
2. `./build.sh <game>` (bare `./build.sh` builds only `game/`) → `dist/<game>/`; serve with `python3 -m http.server -d dist/<game>`.
3. `node tools/run.mjs dist/<game> --fixed-dt 16.666667 --secs 8 --shot s.png` (exit 1 = JS error or WebGPU validation error).
4. `tools/pkgcheck.sh <game>` — ECL never warns about undefined, unexported or engine-redefining functions.
5. **Decide determinism now, not later**: if you will ever want replays, CPU-vs-CPU balance gates or a native sim
   runner, use fixed 60 Hz steps (`run-fixed-steps`), vpads for every input source (keys, touch, CPU), `sim-rnd01`
   only inside the step (`rnd01` for cosmetics), one per-match reset, and a periodic state-hash line. Retrofitting
   this cost the exemplar several sessions. → **REQUIRED SUB-SKILL:** sim-balance-gates.
6. Split pure rules (plain CL, host-tested in ~1 s) from systems; one `tuning.lisp` for every knob; claim a
   `Module._debug_cmd(n)` integer range and a page-storage key range and write them in a table.
7. In a separate repo: copy `engine/`, `vendor/`, `tools/`, `build.sh`, `compile_flags.txt` from the exemplar; keep
   the engine unforked until a second game needs a change (harvest rule).

## Quick reference: the gotchas that cost the most
| Symptom | Cause → rule |
|---|---|
| Random memory corruption / objects vanishing | Boehm can't see wasm locals → GC only between frames; never `(ext:gc)` from Lisp; C statics holding Lisp objects need `ecl_register_root` |
| High cons/frame, GC hitches | single-floats box in lets, slots, defvars, non-inlined calls → `defun-fast`, `let*`, f32vecs, `!` fns, `f-min`/`f-max`, no `incf aref`; budget tens of KB/frame |
| Startup heap spike | heavy meshgen/synthesis/hulls in one step → split into many `:load` steps (GC runs between) |
| "function X is undefined" only in the browser | unexported engine symbol / defined nowhere → `pkgcheck.sh` after every batch |
| Redefining a function after `load` changes nothing | ECL compiles direct calls → patch the source and rebuild |
| emcc -O2 takes minutes on one file | many `handler-case`/`unwind-protect` (setjmps) in one function → one handler per frame, small functions |
| `call_indirect` trap with no message | missing `-DECL_C_COMPATIBLE_VARIADIC_DISPATCH` on a C compile |
| Bignum per call in an RNG | fixnums are 30-bit on wasm32 → RNG in C (`engine/c/rng.c`) |
| Float crash in a rare branch | `pi` is a double → single-float constants |
| WebGPU errors, blank frames | never call blocking SDL_GPU fns; NULL swapchain = skip frame; no `sampler`/`read`/`write` in WGSL binding names |
| Native and wasm results drift | glibc vs musl libm last bit; x87 math → same musl via `LD_PRELOAD`, `-msse2 -mfpmath=sse -ffp-contract=off` |
| User's browser runs old code | a native/test build doesn't touch `dist/` → finish with `./build.sh <game>`, check `index.wasm` newer than every edited source |

## Common mistakes
- Writing gameplay before build + headless run + pkgcheck are green.
- Editing `engine/` in the tree other agents build from (build reads Lisp first, C minutes later) → use a worktree.
- Moving code into the engine with one user; prove other games unchanged after a harvest (frozen stills, CvC hashes, C diff).
- Judging speed on SwiftShader (it runs both sides of branches) — compare before/after only; get a human playtest for feel.
- Waiting on jobs with `pgrep -f`/`pkill -f` patterns that match the waiting shell → wait by PID or notification, bounded loops.
