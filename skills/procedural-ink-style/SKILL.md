# A coherent style with no asset files

## Overview
In the exemplar (`toonnyy8/ai-cl-game-test`, local `/media/8tsp/projects/ai-cl-game-test`; SOUL DUEL's manga-ink
look, RAVEN EDGE's low-poly neon) every body, clip, effect, glyph and sound is generated by code. Core principle:
**the style is written as numbers and tested like code, and presentation is strictly cosmetic** — the sim never reads
it, so art can change freely while the determinism gate proves gameplay did not. Evidence and recipes: `reference.md`;
the full design record: `docs/STYLE_STORM_DESIGN.md`.

## Before drawing anything
1. Research the reference style with graded claims ([V] verified / [V2] / [I] inferred / [U] never used); list the
   traits to copy and the incidental ones to skip.
2. Write the style as numbers: a value-step table, world saturation cap, ≤ 3 spot hues each with an owner and a pixel
   budget, an edge rule, effect step rates per material. Contrast belongs to the characters; colour means something.
3. The user decides from **stills at a few review gates**, with questions that carry a default. Record their words,
   the decision and its consequence in the design doc; log reversals so they stay closed.

## Authoring rules
- Attack clips: `defstrike name (S A R :base stance)` puts the hit pose on the first active frame. Pose to pose: held
  wind-up → `:s :snap <hit-pose>` → overshoot through `:a` → settle → `(:end stance)`. `:root :f` lunges are cosmetic;
  real displacement is the move's `:slide`. Re-time with clip speed instead of re-keying.
- **Drawn reach = hit reach**: the host test runs real FK over the art files and wants the weapon tip within ±0.15 m of
  the hit volume (`tests/duel-rules-test.lisp`, "the volume ends"; it walks J / K links and the Breaker — add any new
  move kind to its coverage). When they disagree, decide which number balance
  depends on and change the other — usually the art.
- Bodies: shapes per rig joint, data-driven proportions (`:props`, `:girth`), variants share rig and hurt volume.
  Round normals and no jitter on toon bodies; never translucent bodies (flash-white / ink silhouette instead).
- Effects: vector ink shapes on one shared fx clock; every one-shot written as an `fx-envelope` call; ≤ 3 hues; never
  step a position the gameplay depends on.
- Events report, presentation shows: rules emit events, one feedback system turns them into sound/sparks/shake.
  Cosmetics use `rnd01`; hitstop and cinematic length are sim timing.
- Cinematics: `defcine` on sim frames (`at` = sim events, `during` = looks) with a written shot grammar; pace with fewer,
  longer shots and keep impact frames sharp.
- Every delayed move has a drawn tell that the CPU reads too; counters get a unique colour + screen event.
- Captions: bake a licensed font offline into committed polygons; test that no caption leaves the screen.
- Audio: `defsound` bank, normalise, DC-block, fold loops, one sound per load step, a C mixer that never touches Lisp
  objects; silence before impacts is a beat.

## Verification (every look change)
| Check | How |
|---|---|
| Gameplay unchanged | G2 CvC hash lines identical (`tests/style-gates.py cvc`) |
| Other game unchanged | its frozen stills byte-identical (new paths are separate entry points defaulting off) |
| Reproducible stills | `node tools/run.mjs DIST --fixed-dt 16.666667 --script steps.json`; scenes as debug integers; contact sheets for the user |
| Style rules | pixel checks (`tools/toon_check.py`: value steps, chroma, spot share, outline continuity) |
| 0 B per frame | a debug probe draws the new path N times and logs its consing; tests want 0 B |
| Art vs hit | the host FK reach test above |

## Common mistakes
- Adjectives instead of numbers ("moody", "punchy") — nothing to gate.
- Shrinking a hitbox to match short art and silently breaking balance; or lengthening art without rerunning the gates.
- Claiming a look is right without a still the user has seen — say "checked by numbers, needs your eyes".
