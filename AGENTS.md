# AGENTS.md — working on this repo

Read this first. It is the map; the detail lives in the files it points to. The user-facing overview is `README.md`
(zh-TW); the doc index is `docs/README.md`.

## What this is

- **Two games on one Common Lisp engine**, compiled ECL → C → wasm (Emscripten) and drawn with SDL3's SDL_GPU on
  WebGPU. Every mesh, clip, effect, glyph and sound is generated by code; there are no asset files.
  - **RAVEN EDGE** (`game/`): a Ninja Gaiden 4–style action game. Finished; changes are rare.
  - **SOUL DUEL** (`duel/`): a BLEACH Rebirth of Souls–style 1v1 3D arena fighter, TYBW roster. All current work is here.
  - `examples/hello` (the minimal game, the template) and `examples/engine-demo`.
- **Repo**: `github.com/toonnyy8/ai-cl-game-test`, **public**, branch `main`. GitHub Pages serves the `gh-pages` branch
  (SOUL DUEL only), published by `tools/deploy-pages.sh`.
- **Babylon port** (`babylon/`, TypeScript): **discontinued 2026-10-06** and frozen at the 2026-10-05 Lisp. Never mirror a
  Lisp change into it (`docs/babylon/BABYLON_PORT.md`).

## Working with the user (standing rules)

- The user calls the assistant **萊醬**. Reply in **Traditional Chinese (zh-TW)**: concise, what changed, the key numbers,
  what is pushed, what is pending, any decision they must make.
- Languages: code comments and design docs in **English**; user-facing docs (`*.zh-TW.md`, `duel/web/manual.html`) in
  **zh-TW**; skills in English.
- **Every user decision goes into the repo docs in the same pass**, never only a scratchpad: the feature's design doc §
  (quote the request verbatim, knobs old → new, tests, gate numbers), a new `docs/DEVLOG.zh-TW.md` § (`## N. 標題
  （YYYY-MM-DD）`, opening `使用者：「…」`), the manual / tutorial if players see it, and every place a changed reference
  number is quoted.
- **Commit and push `main` yourself at each gated milestone**, with the session's attribution trailers. Subject = the
  change, "(the user, YYYY-MM-DD)", key numbers, doc § refs.
- **Never commit** `.claude/`, scratch files, `.refs/` (third-party reference art), `*.pyc`, or regenerable
  `tests/shots/` churn (see `.gitignore`). Research goes in only when it is moved under `docs/research/` (below).
- **Deploy (`tools/deploy-pages.sh`) only when the user asks.** Pushing `main` does not deploy.
- **Rebuild what the user runs**: after any Lisp change, finish with `./build.sh duel` (the native sim gate does not
  touch `dist/`). `dist/duel/index.wasm` must be newer than every edited source.
- **Bounded waits only.** Wait on a PID or a notification; never `pkill -f` / `pgrep -f` patterns (they match the waiting
  shell and never end). Put this rule in every subagent brief.
- Big work: fan out independent batches, one git worktree + branch + fresh subagent each, a compact brief; the lead
  re-runs the tests/gates, merges, pushes. Subagents never push or deploy.
- Ask with `AskUserQuestion` (2–4 options, recommended first) only when the answer changes the design; small clear
  requests get no questions.

## Build and run

```sh
./build.sh duel                          # SOUL DUEL -> dist/duel/   (bare ./build.sh builds only game/)
./build.sh examples/hello                # any dir with a MANIFEST -> dist/<name>/
python3 -m http.server -d dist/duel 8000 # file:// cannot load wasm
node tools/run.mjs dist/duel --fixed-dt 16.666667 --secs 8 --shot s.png   # headless Chrome; exit 1 = JS / WebGPU error
tools/pkgcheck.sh duel                   # ECL never warns about undefined / unexported / engine-redefining functions
```

- A build target is a directory with a `MANIFEST` (first line `# title: NAME`, then sources in dependency order; `.lisp`
  are concatenated into one ECL unit after the engine's, `.c` go to emcc). Errors: `build/<name>/lisp.log`, line numbers
  refer to `build/<name>/game-all.lisp`.
- Toolchain paths (overridable by env, see `README.md` 需求): host ECL `ECL_HOST`
  (`/media/8tsp/projects/ecl-24.5.10/ecl-emscripten-host/bin/ecl`, 32-bit), `EMSDK_DIR` (`/media/8tsp/projects/emsdk`, 4.0.12).
- `Module._debug_cmd(n)` drives debug scenarios; SOUL DUEL's integer ranges are in `docs/duel/DUEL_GAMEPLAY.md`
  "Debug commands" (claim a new range there before using it).

## SOUL DUEL architecture in one screen

- **Roster**: index 0 Yamamoto (`yama*.lisp`), 1 Kenpachi (`ken*`), 2 Rukia (`rukia*`), 3 Ichigo (`ichigo*`),
  4 Senjumaru (`senjumaru*`). Each character = data + hooks: `defkit` forms with `:ai` plists, `defmove`s, its own CPU
  functions (`:reflex`, `:opp-reflex`, `:sp-ender`, `:sig-hold`, `:assist-guard`), cinematics; art in `<char>-art.lisp`
  (`defstrike` clips, bodies).
- **Plain CL, host-tested**: `tuning.lisp` (every knob, `defparameter` + docstring with old → new, date, who decided),
  `rules.lisp`, `control.lisp`, `learn.lisp`, `kit.lisp` (`parse-move`, reach floors). **Systems**: `fighter`, `combat`,
  `hazards`, `ai`, `assist`, `camera`, `feedback`, `flow`, `hud`, `onehand`, `endless`, `debug` (debug commands, gate
  scenarios), `main`; shared look: `body`, `brush`, `vfx`, `stage`, `cinema`, `glyphs`, `sounds`. Compile order:
  `duel/MANIFEST`.
- **Determinism**: fixed 60 Hz steps, vpads for every input source (keys, touch, CPU), `sim-rnd01` inside the step only
  (`rnd01` for cosmetics), per-match reset, periodic state-hash lines. The native sim and the browser must agree bit for bit.
- **Presentation is cosmetic**: the sim never reads art. Drawn reach must equal hit reach (host FK test, ±0.15 m).
- **CPU**: `ai.lisp` (generic) + each kit's reflexes (AI v2, `docs/duel/DUEL_AI_V2.md`); every chance scales by difficulty
  EASY ≤ NORMAL ≤ HARD; roll once per event, never per step. Learning CPU `learn.lisp` (`DUEL_LEARNING.md`); ASSIST /
  AUTO modes `assist.lisp` (`DUEL_ASSIST.md`).
- **Performance rules** (engine-wide): GC only between frames; 0 B/frame for new draw paths; split heavy startup work into
  `:load` steps; `defun-fast` / f32vecs to avoid float boxing. Details: `docs/engine/ARCHITECTURE.md`.

## Gotchas that cost the most

- Boehm can't see wasm locals: never `(ext:gc)` from Lisp; C statics holding Lisp objects need `ecl_register_root`.
- Redefining a function after load changes nothing (ECL compiles direct calls): edit the source and rebuild.
- Many `handler-case` / `unwind-protect` in one function make emcc take minutes.
- Fixnums are 30-bit on wasm32 (RNG lives in C); `pi` is a double (use single-float constants).
- Native vs wasm drift comes from libm / x87: the sim gate uses musl and `-msse2 -mfpmath=sse -ffp-contract=off`.
- WebGPU: never call a blocking SDL_GPU function (skip the frame when the swapchain texture is NULL); WGSL variable
  names must not contain `sampler` / `read` / `write` (the backend scans the WGSL text for its bind layouts).
- SwiftShader runs both sides of branches: compare speed before/after only; feel needs a human playtest.
- A per-step random chance is a certainty; a reaction slower than the threat never fires.
- More in `docs/guides/PLAYBOOK.zh-TW.md` (appendix) and `docs/engine/ARCHITECTURE.md`.
